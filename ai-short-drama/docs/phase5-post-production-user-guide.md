# 第五阶段创作工作台使用说明

## 进入工作台

在项目详情选择单集并打开“统一创作工作台”，或直接访问：

```text
/projects/{projectId}/episodes/{episodeId}/workbench
```

页面顶部显示当前单集、模板和时间线版本。六个页签共用同一组实体 ID，因此从质量问题、对白或分镜切换页面不会创建重复数据。

## 推荐操作顺序

1. 在“剧本与节拍”核对诊断、情绪曲线和节拍时长，拖拽场景卡调整顺序。
2. 逐句编辑对白，或将对白转换为旁白/动作。
3. 在“分镜故事板”查看缩略图，创建拆分、合并、换序或调时长计划。
4. 在“口型与声音”运行说话人、口型偏差、配音时长和多人轮次校验。
5. 核对 BGM、环境声、脚步、门响、打斗等正式 cue 的时间码和授权。
6. 在“剪辑时间线”应用类型模板或切换整集声音风格。
7. 在“连续性与 QC”处理可跳转的问题。
8. 在“候选与版本”比较时间线并按需恢复旧版本。

## 剧本、场景与分镜编辑

逐句对白编辑、对白转旁白/动作、场景拖拽以及镜头结构操作都会先创建 `change-plan.v1`。页面显示预计字段 diff、保留项、受影响 artifact 和重建任务。只有明确确认并执行后才创建正式后继版本。

对白修改的精确重建范围来自该句当前字幕/配音时间：

- 新对白和配音版本；
- 新字幕 cue；
- 引用该句的镜头区间；
- 当前剪辑时间线的同一区间。

其他台词、场景、声音 cue 和镜头不重建。不要通过直接改数据库或覆盖媒体文件跳过该流程，否则来源链和恢复能力会失效。

镜头拆分、合并和换序会创建结构化局部修改计划，并要求保留人物状态、动作接力和镜头轴线。当前页面不是自由覆盖式 NLE；修改会交给既有局部修改执行链物化为版本。

## 口型和对白校验

“运行口型/轮次校验”会检查每句对白的：

- 说话人与画面可见人物；
- 检测说话人与指定说话人；
- 音频开始/结束与目标口型区间；
- 配音是否超出镜头可用时间；
- 多人对白的轮次、重叠和顺序。

默认偏差容差为 120 ms。配音过长时优先处理文案和停顿，其次考虑延长镜头；只有小幅修正才使用有限变速。worker 会拒绝超过 1.12 倍的加速。

问题卡可跳至对应编辑位置并创建局部修改计划。修复后重新校验，只重建相关区间。

## BGM、音效与环境声

声音页按轨道显示 BGM、环境声、音效、脚步、门响、打斗、对白和旁白。每个正式资产应包含来源、内容版本、情绪、BPM/节拍、调性、时长和授权元数据。

cue 可包含：

- 与画面事件对齐的开始/结束时间码；
- 卡点偏移；
- 淡入、淡出和增益；
- 明确的半音转调；
- 对白 ducking 参数。

“整集声音风格替换”会为当前 cue 建立目标风格的后继版本和新时间线，不删除原声音版本。目标风格组必须覆盖当前使用的全部声音类型；缺少任一类型时操作会失败并保持原 current。

## 类型化剪辑模板

内置模板：

- 都市爽剧；
- 情感剧；
- 悬疑剧；
- 喜剧；
- 动作剧。

选择模板版本和作用域后应用。项目级模板是默认值，单集级模板优先。应用会产生新时间线版本，控制平均镜头长度、快切/反应镜头、转场、字幕、声音密度、特写、停顿、重复强调和节拍策略。

切换模板不会覆盖旧时间线。可在版本页比较模板版本、父时间线、审批状态和创建原因。

## 评论、问题跳转与局部修改

评论可绑定当前场景、某句对白或某个镜头，也可填写毫秒时间码。质量、连续性、视觉 QC 和口型问题保留实体/时间码定位；点击问题会打开对应的局部编辑位置。

从问题创建修改计划时，先检查：

- 目标实体和版本是否正确；
- `must_preserve` 是否包含人物身份、剧情事实和连续性；
- 影响列表是否只包含预期区间；
- 是否需要重新做视觉 QC、口型或最终 QC。

## 版本比较与恢复

版本页可查看候选、工作台快照和所有时间线版本。恢复任意旧时间线会创建一个新的 `restored` current 版本；被选中的旧版本、当前版本和其媒体资产均保留。

模板切换、声音风格替换、对白修改和恢复都应能在版本历史中看到父版本和原因。恢复后再次运行受影响的 QC，确认新 current 符合发布门禁。

## API 参考

后期工作台 API 合同位于 `contracts/openapi/post-production-api.v1.yaml`。主要接口：

- `GET .../creative-workbench`
- `POST .../dialogue-timings/validate`
- `GET .../editing-templates`
- `POST .../editing-template`
- `POST .../sound-style`
- `GET .../timeline-versions`
- `POST .../timeline-versions/{timeline_id}/restore`

公共数据合同位于 `contracts/json-schema/`。自动化客户端应根据 OpenAPI/Schema 构造请求，不依赖页面内部字段。
